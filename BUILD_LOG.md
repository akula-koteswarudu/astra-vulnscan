### Step 9: Student baseline scan — first attempt stopped (Groq output limit)
- First real run (`2026-11-14T1623_insecureshop_912c2e04`) stopped by me after unit 3/17: Groq rejected requests with "Request too large … output tokens per minute (OTPM): Limit 1000, Requested 1500". A probe (`ProviderSmokeTest#probeGroqOutputLimits`) confirmed `qwen/qwen3.8-27b` rejects `max_tokens` > 1,000; `openai/gpt-oss-120b` accepts 4,000. The two finished units used 1,317–1,554 output tokens for 6–7 findings (~200 tokens per finding).
- **DEVIATION (config + small code change, consequence of the real limits):** student `max_output_tokens` 1000 and `rate_limit.otpm` 1000; student `planning_budget_tokens` 4900 (the plan's own "what we choose to send per request" field) so the per-request cap stays 4,900 and the unit plan stays at 17 units of ≤ 2,400 code tokens. The limiter now fails fast when `max_tokens` exceeds `otpm`; the scanner caps the doubled retry at the output limit and, when doubling is impossible, goes straight to re-planning the unit into per-file units. Groq's "Request too large" 429 is now non-retryable (waiting cannot help). 3 new tests (115 total).
- Throughput consequence: with 1,000 output tokens per minute the student runs at about one request per minute; one student arm takes roughly 20–30 minutes.
